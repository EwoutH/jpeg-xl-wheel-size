# Pillow JPEG XL wheel-size experiments

This repository measures the cost of adding JPEG XL decoding to Pillow. It builds
real CPython 3.13 wheels on Linux (manylinux x86_64 and aarch64), macOS (Intel and
Apple Silicon), and Windows (AMD64), using Pillow's own dependency recipes and
cibuildwheel configuration. Nothing is uploaded to PyPI.

Pillow source is pinned to `olokelo/Pillow@d00ba3a89faabd31fd92c3b506c86557da8c0a0b`
(the head of PR python-pillow/Pillow#7848 when this experiment was prepared).
libjxl is version 0.11.2, as specified by that commit.

| Variant | Change from previous variant |
| --- | --- |
| `no-jxl` | Same source/dependencies as `pr`, JPEG XL extension explicitly disabled |
| `pr` | Original PR build settings |
| `decoder` | Link upstream `jxl_dec` instead of `jxl`; install the existing decoder target on Unix; omit encoder-only Brotli link on Windows |
| `minsize` | Decoder build with `CMAKE_BUILD_TYPE=MinSizeRel` |
| `lto` | MinSizeRel plus `CMAKE_INTERPROCEDURAL_OPTIMIZATION=ON` |
| `scalar` | LTO plus `HWY_COMPILE_ONLY_SCALAR` (experimental speed/size tradeoff) |

The decoder variants also disable tools, examples, JNI, benchmarks, jpegli and
documentation. This reduces build work; these are not themselves assumed to
reduce the wheel payload. Box metadata and JPEG reconstruction support remain
enabled. The experiment does not remove format features to make the numbers
look smaller.

Each build runs Pillow's selftest, asserts whether JPEG XL is present, runs the
PR's image/animation/metadata tests and JPEG/PNG regression tests, and records
pixel hashes and warm decoding timings for six JPEG XL images. A missing JPEG
XL extension fails the build rather than silently skipping all its tests.
Timing comparisons across independent hosted runners are noisy; use repeated
benchmarks on the same machine before making a performance decision.

Artifacts contain the wheel, total ZIP bytes, total uncompressed bytes,
per-member sizes, SHA-256 checksums, pixel hashes/timings, and applied patch.
Wheel ZIP bytes represent download/storage cost. Uncompressed member bytes
approximate installed size (excluding generated bytecode and filesystem blocks).

Run the **Wheel size experiment** workflow manually. The 30-job matrix is
limited to 10 simultaneous jobs. Reproduce a source patch with:

```console
python scripts/prepare.py /path/to/fresh/Pillow decoder
```

Fresh source and isolated dependency prefixes are required for each variant;
no cross-variant cache is used. Comparisons use the same source commit, Python
ABI, architecture and base dependencies, rather than comparing against an
unrelated released Pillow wheel.

Research sources:

- https://github.com/python-pillow/Pillow/pull/7848
- https://github.com/python-pillow/Pillow/issues/9101
- https://github.com/libjxl/libjxl/blob/v0.11.2/lib/jxl.cmake
- https://github.com/libjxl/libjxl/blob/v0.11.2/CMakeLists.txt
- https://github.com/google/highway/blob/1.3.0/hwy/detect_targets.h

Separate optional plugin wheels (potentially exposed through `pillow[jpegxl]`)
remain an architectural alternative: users who do not install the extra incur
no codec binary cost. This experiment first asks how small native inclusion can
be, without requiring a packaging redesign.
