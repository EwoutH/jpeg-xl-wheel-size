# Pillow JPEG XL wheel-size experiments

**Complete:** 30 wheels across five platforms, all selected test jobs passing.
Decoder-only linking removes 66–68% of JPEG XL's added Linux/macOS download
cost; MinSizeRel + LTO removes about 80–82%, with platform-specific decoding
tradeoffs. ZIP level 9 separately saves 3.0–3.7% on Linux.

This repository measures the cost of adding JPEG XL decoding to Pillow. It builds
real CPython 3.13 wheels on Linux (manylinux x86_64 and aarch64), macOS (Intel and
Apple Silicon), and Windows (AMD64), using Pillow's own dependency recipes and
cibuildwheel configuration. Nothing is uploaded to PyPI.

Pillow source is pinned to `olokelo/Pillow@d00ba3a89faabd31fd92c3b506c86557da8c0a0b`
(the head of PR python-pillow/Pillow#7848 when this experiment was prepared).
libjxl is version 0.11.2, as specified by that commit.

The staging harness skips Highway's standalone tests/examples. For the PR
baseline it also disables standalone libjxl tools/benchmarks, whose executable
link fails against the common non-PIE libsharpyuv archive on Linux x86_64.
These executables are not wheel payload; the baseline's library and compiler
settings remain those of the PR.

| Variant | Change from previous variant |
| --- | --- |
| `no-jxl` | Same source/dependencies as `pr`, JPEG XL extension explicitly disabled |
| `pr` | Original PR build settings |
| `decoder` | Link upstream `jxl_dec` instead of `jxl`; install the existing decoder target on Unix; omit encoder-only Brotli link on Windows |
| `minsize` | Decoder build with `CMAKE_BUILD_TYPE=MinSizeRel` |
| `lto` | MinSizeRel plus `CMAKE_INTERPROCEDURAL_OPTIMIZATION=ON` |
| `scalar` | LTO plus `HWY_COMPILE_ONLY_SCALAR` (experimental speed/size tradeoff) |

The decoder variants also disable tools, examples, JNI, benchmarks, jpegli and
documentation. This reduces build work; these are not themselves assumed to
reduce the wheel payload. Box metadata and JPEG reconstruction support remain
enabled. The experiment does not remove format features to make the numbers
look smaller.

Each build runs Pillow's selftest, asserts whether JPEG XL is present, runs the
PR's image/animation/metadata tests and JPEG/PNG regression tests, and records
pixel hashes and warm decoding timings for six JPEG XL images. A missing JPEG
XL extension fails the build rather than silently skipping all its tests.
Timing comparisons across independent hosted runners are noisy; use repeated
benchmarks on the same machine before making a performance decision.

Artifacts contain the wheel, total ZIP bytes, total uncompressed bytes,
per-member sizes, SHA-256 checksums, pixel hashes/timings, and applied patch.
Wheel ZIP bytes represent download/storage cost. Uncompressed member bytes
approximate installed size (excluding generated bytecode and filesystem blocks).

Run the **Staged wheel size experiment** workflow manually. Each platform builds
its common dependencies and baseline wheel once, then fans out the JPEG XL
variants. There is no imposed 10-job concurrency cap. GitHub account and runner
capacity still limit actual concurrency. Reproduce a source patch with:

```console
python scripts/prepare.py /path/to/fresh/Pillow decoder
```

Each variant gets fresh source and restores the same immutable common dependency
bundle into a fresh runner/container. Comparisons use the same source commit, Python
ABI, architecture and base dependencies, rather than comparing against an
unrelated released Pillow wheel.

Common bundles are cached across runs with exact keys covering the platform,
runner image version, pinned Linux container digest, dependency versions,
recipes and staging scripts. No broad fallback keys mix binary versions.
The installed prefix is archived, rather than the much larger source/build
trees. Each archive has a SHA-256 checksum and fixed install-prefix check.
Linux variants use the same container digest as their common stage.

Wheel building, measurement/upload and testing are separate stages. Wheels are
saved before tests run, so failed test jobs can be rerun without recompiling.
Dependency artifacts last 14 days; wheels and verification artifacts last 30
days. Common libraries are shared, while each libjxl variant builds separately
to preserve a fair comparison. The `no-jxl` variant reuses the saved baseline
wheel and performs no additional build.

Use the `targets` input (for example `windows-amd64` or
`linux-x86_64,macos-arm64`) to avoid scheduling other platforms. Use `variants`
to select a JSON list. Tests produce JUnit XML alongside pixel hashes/timings.

For a retry, set `dependency_run` to a previous successful common-stage run ID
to reuse its archived dependencies and baseline wheel without compilation.

Run **Report saved wheel measurements** with comma-separated build run IDs to
refresh results without building anything. It reuses the matching and table
rendering functions from Pillow's own
[PR #9621](https://github.com/python-pillow/Pillow/pull/9621), unchanged at the
pinned source commit. `UPSTREAM-COMPARISON.md` includes PyPI and same-commit
comparisons; `pypi-baseline.json` records the release and fetch date.
`RESULTS.md` adds installed/member sizes, decoding checks, pytest counts and
verified ZIP recompression measurements. The PyPI comparison includes other
Pillow changes; use the same-commit baseline to isolate JPEG XL's cost.

The **Compare decoding from saved wheels** workflow installs each saved variant
in a separate directory and compares samples sequentially on one runner. This
quantifies channel differences and reduces CPU variation in timing comparisons.
It also performs no compilation. Supply a build run, target and matching runner.

Run `python scripts/check_pipeline.py` locally after checking out the pinned
Pillow source to validate stage partitioning and dependency archive integrity.

Separate optional plugin wheels (potentially exposed through `pillow[jpegxl]`)
remain an architectural alternative: users who do not install the extra incur
no codec binary cost. This experiment first asks how small native inclusion can
be, without requiring a packaging redesign.
